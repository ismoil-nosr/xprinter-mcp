# Быстрый запуск через Docker

[English](DOCKER.md) · **Русский** · [简体中文](DOCKER.zh-CN.md)

Готовый образ **`ghcr.io/ismoil-nosr/xprinter-mcp:0.2.0`** поддерживает Intel/AMD (`linux/amd64`) и ARM (`linux/arm64`). В нём уже есть Node 24, MCP-сервер, зафиксированные зависимости и SSH. Он запускается в Docker Desktop на Mac/Windows и Docker Engine на Linux. Для воспроизводимого запуска используйте версию или digest из релиза; `latest` обновляется с релизами.

MCP работает **в контейнере**, а USB-принтер подключён к Mac с установленным [Open Xprinter 0.3.0+](https://github.com/ismoil-nosr/xprinter-macos/releases/latest) и настроенной очередью `XP330B_OpenSource`. Контейнер вызывает генератор этикеток и CUPS на Mac через SSH. **Node и пакет MCP на Mac с принтером устанавливать не нужно.** Нужны обычный авторизованный Mac-аккаунт с SSH, доступная сеть и бодрствующий Mac. Прямой USB-бэкенд для Linux/Windows пока не реализован.

Docker Desktop [не предоставляет прямую передачу USB](https://docs.docker.com/desktop/troubleshoot-and-support/faqs/general/#can-i-pass-through-a-usb-device-to-a-container); Linux-контейнер также не запускает macOS AppKit. Привилегированный контейнер, Docker socket, общий доступ к CUPS и открытый порт принтера не требуются. Сохраняются все восемь инструментов, три языка, права OAuth, приватные превью, лимиты и квитанции повторов.

## Подготовить Mac один раз

1. Установите обычный драйвер/приложение, настройте очередь и проверьте реальную этикетку с верными размером и зазором.
2. Включите **Системные настройки → Основные → Общий доступ → Удалённый вход** для разрешённого обычного аккаунта. Ограничьте доступ доверенной LAN/VPN; открывать SSH в интернет не требуется. [Инструкция Apple](https://support.apple.com/guide/mac-help/allow-a-remote-computer-to-access-your-mac-mchlp1066/mac).
3. На компьютере с Docker создайте отдельный ключ:

```sh
mkdir -p secrets
chmod 700 secrets
ssh-keygen -t ed25519 -f secrets/id_ed25519 -N '' -C open-xprinter-docker
```

Добавьте **публичный** ключ `secrets/id_ed25519.pub` в `~/.ssh/authorized_keys` нужного Mac-аккаунта. Перед строкой ключа поставьте `restrict `, чтобы отключить перенаправления, агент и TTY. Каталог `.ssh` должен иметь права 0700, `authorized_keys` — 0600. Этот ключ всё равно позволяет выполнять команды от имени аккаунта; защищайте приватную часть и по возможности используйте выделенный аккаунт. MCP не принимает произвольные команды, но украденный SSH-ключ находится вне этой защиты.

На **самом Mac с принтером** получите публичный ключ сервера и его отпечаток:

```sh
cat /etc/ssh/ssh_host_ed25519_key.pub
ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub
```

На Docker-компьютере создайте `secrets/known_hosts` с проверенным ключом. Для Docker Desktop на этом же Mac:

```text
host.docker.internal ssh-ed25519 REPLACE_WITH_VERIFIED_PUBLIC_HOST_KEY
```

Используйте то же имя/IP, что в `XPRINTER_SSH_HOST`; для нестандартного порта формат имени — `[host]:port`. Для удалённого Mac сверяйте отпечаток по доверенному каналу. Один `ssh-keyscan` не подтверждает подлинность сервера. Новый или изменившийся ключ не принимается автоматически. В этом фоновом режиме ключ не должен требовать интерактивного ввода парольной фразы.

## Скачать, проверить и подключить

Скачайте `xprinter-docker-0.2.0.zip` и `SHA256SUMS.txt` из [релиза](https://github.com/ismoil-nosr/xprinter-mcp/releases/tag/v0.2.0), проверьте SHA-256 и распакуйте. Можно также клонировать репозиторий. Скопируйте `docker.env.example` в `docker.env` и задайте имя Mac-аккаунта, адрес Mac и пути к двум SSH-файлам. Укажите `XPRINTER_LANGUAGE=ru`.

`host.docker.internal` подходит для Docker Desktop на Mac с принтером; на другом компьютере укажите доступное имя/IP этого Mac. `localhost` в контейнере означает сам контейнер. Приватный ключ должен иметь права 0600, оба файла — быть читаемыми для UID 1000 в контейнере; не открывайте приватный ключ всем пользователям. Если владельцы файлов мешают доступу, используйте [отдельный том ключей и готовую команду инициализации](DOCKER.md#ownership-troubleshooting).

```sh
docker compose --env-file docker.env pull xprinter
docker compose --env-file docker.env run --rm -T xprinter doctor
```

Проверка должна показать `backend: "ssh"`, настроенную очередь и `rendering: true`. Она не двигает бумагу; состояние очереди не доказывает наличие принтера или правильный рулон. Для stdio:

```sh
docker compose --env-file docker.env run --rm -T xprinter
```

Для AI-клиента есть [готовый JSON](../examples/docker.json): замените абсолютные пути к Docker/SSH-файлам и имя аккаунта. Docker должен работать. Нужен `-i`, **без `-t`**: TTY повреждает MCP-поток. Внешний формат конфигурации зависит от AI-приложения.

По умолчанию `XPRINTER_ALLOW_PRINT=0`. После проверки превью и рулона включите `1` и настройте собственные подтверждения инструментов в AI-клиенте. Поле, которое передаёт AI, не доказывает согласие человека. Печать не запустится без постоянного тома квитанций.

## Сохранить квитанции и лимиты

Все контейнеры этого принтера должны использовать общий именованный том **`xprinter-mcp-state`** и одинаковые лимиты. Он хранит приватные этикетки и квитанции, сохраняется после `--rm`, обновления и пересоздания. Не удаляйте его через `down -v`, очистку томов или удаление приложения: это удалит защиту от повторной печати.

Том привязан к одному SSH-адресу/порту/аккаунту. При `backend_changed` восстановите прежние настройки; прежде чем создавать другую установку, разберите незавершённые/неизвестные задания. Отдельный MCP на Mac или другой том имеют собственные лимиты, поэтому для принтера используйте одну основную установку. Другие Mac-приложения печатают вне лимитов MCP. При `uncertain` проверьте очередь и бумагу, сохраните тот же ключ запроса; не перепечатывайте автоматически с новым UUID.

## Постоянная служба HTTPS

Задайте реальный HTTPS-адрес, OAuth issuer и JWKS URL в `docker.env` по [контракту OAuth](OAUTH.md) и [инструкции удалённого доступа](REMOTE.md):

```sh
docker compose --env-file docker.env --profile http up -d xprinter-http
docker compose --env-file docker.env --profile http ps xprinter-http
```

В контейнере слушается `0.0.0.0`, а на Docker-компьютере Compose открывает **только `127.0.0.1:8787`** для настроенного вами HTTPS-прокси. OAuth обязателен; анонимного MCP HTTP нет. Healthcheck проверяет доступность метаданных, а не USB, бумагу или вход через OAuth. Не публикуйте незашифрованный порт в интернет. Проверенные OAuth-пользователи сохраняют отдельные идентичности и приватные данные.

## Проверка разработки в клоне репозитория

```sh
docker build -t xprinter-mcp:docker-test .
npm ci --ignore-scripts
npm run test:docker
```

Node нужен только компьютеру разработчика для тестового клиента. Тест запускает настоящий контейнер и SSH с синтетическим принтером, проверяет оба режима MCP, пересоздание, квитанции, отмену, потерю ответа, неверный ключ сервера и обязательный OAuth. Физический принтер этому тесту недоступен. CI проверяет AMD64/ARM64 до публикации образов с SBOM и provenance; настоящий генератор отдельно проверяется на macOS. [Границы проверки](VALIDATION.md).
